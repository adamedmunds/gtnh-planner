# Build in 3D (Project 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** "Build in 3D" turns a solved Calculator line into a buildable 3D layout (modular core + copy-paste slices, or a straight line), with power up to HV, markers for inputs/outputs, "+ slice" growth and a one-slice schematic export.

**Architecture:** Three pure stages in `src/layout/`: **plan** (from the solved chain: which machines repeat in slices, which live in the core, which resources need networks, power per tier), **place + route** (put machines on the B cross-section around a walkway, then connect every network with the existing `routeNetwork` router, widening the slice and retrying until everything routes), and **check** (an independent build checker that proves every machine gets its inputs, its output, and power of a safe tier, and that slices are identical). The UI only calls these and loads the result into the editor.

**Tech Stack:** TypeScript, React 19, existing model/catalog/exporter, Vitest, Playwright. GT data: GregTech 5.09.54.183 (`.downloads/gt5-5.09.54.183`, read with `git show HEAD:<path>`).

**Spec:** `docs/superpowers/specs/2026-10-19-build-in-3d-design.md` (approved).

## Global Constraints

- Coordinates: x along the line, y up, z across. Walkway at z = 0, y = 0..1, always air. Modular rows: machines at z = −1 and z = +1, y = 0 (bottom) and y = 1 (top). Straight line: machines at z = −1, y = 0 only.
- Facing: `PlacedBlock.facing` is the machine's output side (GT `mFacing`), as in `src/presets/oilBerryLine.ts`. Generators output on their facing side; a transformer's facing side is its high-voltage input (step-down), all other sides are low-voltage output.
- Pipes/cables connect only where the generator sets `manualMask` (forcedOn on intended sides, forcedOff on all others), so adjacent networks never join.
- Power up to HV. Cables: LV Tin (1240, 1 A/size), MV Annealed Copper (1380, 1 A/size), HV Gold (1420, 3 A/size); 1x = start + 6, 4x = start + 8, meta 9. Transformers: MV→LV 21, HV→MV 22 (step-down, 4 A out). Anything needing EV+ power → plan error "can't build power for this yet (needs EV)".
- Fluid pipes: Bronze 5120 (base 120), Steel 5130 (240), Stainless Steel 5140 (360), Titanium 5150 (480); size ids start + {small 1, normal 2, large 3}. Capacity per size from GT `FluidPipeBuilder` (verify in source; if not in the sparse clone, use L/t = base × {small 2, normal 6, large 12} and record the ruling).
- Slice counts round **up**; straight-line counts equal the Calculator's "×N to build".
- Plain words in every message the user sees (same bar as the Calculator: no "target", "limit", "external", "maximise").
- Replacing the 3D build, "+ slice" and "− slice" are one undo step each.
- Recipe data, textures and icons stay local and uncommitted.

## Review Focus

1. A line whose machines need more faces than the cross-section gives (e.g. a machine with 2 fluid inputs, 2 outputs and power) → routing widens and still succeeds, or the plan falls back with a plain reason; never a silently unconnected machine. (Task 4 test: chemical reactor + electrolyzer core.)
2. An LV machine anywhere on an MV/HV cable network → the checker reports it; the generator never produces it. (Task 3 + Task 4 tests.)
3. A machine with both a fluid and an item output (chemical reactor: Light Fuel + cells) → second output routed on another face and a cover note ("Fluid Regulator/pump cover on the bottom of the Chemical Reactor") added. (Task 4 test.)
4. Hand edits to a generated build → "+ slice" / "Export one slice" disappear, never corrupt the edit. (Task 6 test.)
5. A line with power from outside (no generator nodes) → "Power in (N EU/t, tier)" marker feeding the highest-tier network, transformers for lower tiers. (Task 4 test.)

### Task 2: Line plan — slices, core, networks, power

**Files:**
- Create: `src/layout/plan.ts`, `src/layout/plan.test.ts`

**Interfaces:**
- Consumes: `ScreenSolve` (`src/calculator/drive.ts`), `Chain`, `RecipeDb`, `nodeRates`, `machineName`, `haveBoxes`, Task 1 types.
- Produces:
  - `type LayoutStyle = 'modular' | 'straight'`
  - `interface PlanMachine { nodeId: string; key: string; machine: GeneratedMachine; tier: 'LV' | 'MV' | 'HV' | ...; count: number; inputs: ResourceKey[]; outputs: ResourceKey[]; generator: boolean }` — `count` = machines per slice (slice stages), per core (core stages) or total (straight).
  - `interface PlanNetwork { key: ResourceKey; kind: 'fluid' | 'item'; flow: number /* per second, whole build */; producers: string[]; consumers: string[] /* nodeIds or marker ids */ }`
  - `interface PowerPlan { tiers: ('LV'|'MV'|'HV')[]; source: { kind: 'generators'; tier } | { kind: 'outside'; tier; eut } ; demand: Record<tier, number /* EU/t */>; transformers: { from; to; count }[] }`
  - `interface LinePlan { style: LayoutStyle; slice?: PlanMachine[]; sliceCount: number; core: PlanMachine[]; coreServes?: number /* slices one core supports */; straight?: PlanMachine[]; networks: PlanNetwork[]; markers: { id: string; key: ResourceKey; dir: 'in' | 'out'; kind: 'item'|'fluid' }[]; power: PowerPlan; notes: string[]; fallback?: string }`
  - `planLine(chain: Chain, db: RecipeDb, screen: ScreenSolve, style: LayoutStyle): LinePlan | { error: string }`
  - Rules (pin these):
    - **Anchor** = the first node consuming the first What I have input; with no have box, the first node consuming any input from outside. `sliceCount = ceil(anchor machines − 1e-9)`; `s_exact = anchor machines`.
    - A node **repeats** (goes in the slice) when `machines / sliceCount ≥ 0.5`; per-slice count = `ceil(machines / sliceCount − 1e-9)`. Others go in the **core** with `ceil(machines)`; `coreServes = min over core nodes of floor(ceil(machines) × s_exact / machines)`.
    - No anchor, or fewer than 2 slices, or no repeating node → `fallback: "This line doesn't repeat, so it's laid out in a straight line."` and the straight plan.
    - Networks: one per resource that flows between machines or to/from a marker; markers for every input from outside (`in`) and the product + every Also made (`out`). EU is power, not a network.
    - Power: tiers present = machine tiers (LV/MV/HV); EV+ → `{ error: "Can't build power for this line yet (needs EV)" }`. Source = generator nodes' tier, else `outside` at the highest machine tier with `eut = euUsed`. Transformers per step-down = `ceil(demand of lower tier (incl. tiers below it) / (V[lower] × 4))`.
    - Multiblock nodes (`MachineRef.multiblock`) go to the core as one `marker_multiblock` cell with the note "Build the <name> here yourself (multiblocks aren't laid out yet)"; their networks still route to that cell.
    - Notes (plain): "6 slices for 5.57 Oil Berry/s · paste more slices on either end to grow it", "This core handles up to 15 slices".

### Task 3: Build checker

**Files:**
- Create: `src/layout/check.ts`, `src/layout/check.test.ts`

**Interfaces:**
- Consumes: `computeConnections`, `catalogFor`, `LinePlan`.
- Produces: `checkLine(build: Build, plan: LinePlan): string[]` — empty when buildable. Checks, each with a plain message naming the block position:
  1. Every plan machine/marker exists; each network is one connected component of same-kind conduits joining all its producers' output faces (the machine's `facing` side, or a cover face listed in `build`'s notes) and all its consumers' non-facing sides.
  2. No conduit connects two different networks or a machine that doesn't use its resource.
  3. Every machine touches a cable network; a network's tier (its source: generator tier, transformer low side, or power marker tier) is ≤ every machine's tier on it; transformers' facing side touches the higher network.
  4. Walkway cells (z = 0, y = 0..1, modular) are air.
  5. Modular: blocks of slice k translated by `k × sliceLength` equal slice 0's (same keys, facings, masks).
- `Build` gains `generated?: GeneratedLine` (defined in Task 4; this task only needs `notes: string[]` for covers — add `notes?: string[]` to `Build` here).

### Task 4: Place and route — modular and straight layouts

**Files:**
- Create: `src/layout/build.ts`, `src/layout/build.test.ts`, `src/layout/power.ts`, `src/layout/power.test.ts`

**Interfaces:**
- Consumes: Tasks 1–3, `routeNetwork` (`src/model/route.ts`).
- Produces: `buildLine(plan: LinePlan, name: string): { build: Build; generated?: GeneratedLine; warnings: string[] }` and, in `power.ts`, `cableFor(tier, amps): string` (smallest catalog cable of that tier carrying `amps`; parallel lanes + warning when 4x isn't enough) and `pipeFor(kind, flow): string` (smallest pipe carrying `flow`, warning "Light Fuel needs more than one large Titanium pipe carries" when none).
- Algorithm (pin):
  1. **Slice template** (modular): place the slice's machines on the B cross-section (both sides, both levels, generators and transformers counted as machines), filling columns x = 0..L−1; start with one empty column between machine columns.
  2. **Through-lanes:** each network or power tier that spans slices gets a lane: a straight line of conduit cells along x at a reserved (y, z) outside the machine cells (first candidates: z = ±2 at y = 0, 1; y = −1 and y = 2 at z = ±1; then z = ±3), running x = 0..L−1 so consecutive slices join.
  3. **Branches:** for each machine and each network it uses, `routeNetwork` connects the lane (terminal = its cells) to the machine (terminal = free neighbour cells; the output network's terminal is chosen first and the machine's `facing` is set to that side; a second output of the other kind (fluid vs item) uses another face and adds the cover note "Add a pump cover (fluids) / conveyor cover (items) on the <side> of the <machine> at (x,y,z)"). Walkway cells and other networks' cells are blocked.
  4. If any route fails, widen the slice by one column (spacing) and retry from 1; give up after 6 widenings with warning "Couldn't fit the pipes for <machine>; laid out in a straight line instead" and fall back to straight.
  5. **Core:** same procedure for core machines in their own block at x = −C..−1 between the left and right slice groups (left slices at negative x mirrored by translation, not reflection — slices must stay identical), with lane ends meeting the slice lanes; markers placed at the core's back (z = ±3 … ) with their networks routed to them.
  6. **Power:** generators' facing toward their tier's cable lane; transformers' facing toward the higher lane; outside power → `marker_power_in` at the core end on the highest lane.
  7. Pipes/cables get `manualMask` from their final network membership. Run `checkLine` on the result; any problem → throw (tests) / warning + straight fallback (runtime).
  - Straight style: machines in chain order along x at z = −1, y = 0, with an empty column between machine groups; lanes behind (z = −2, −3 …) and above (y = 1); same branch routing and power.
  - `GeneratedLine` (also used by Task 6): `{ style: LayoutStyle; sliceLength: number; sliceCount: number; left: number; right: number; template: PlacedBlock[] /* slice 0 */; coreServes?: number; inputsPerSlice?: number }` stored on `build.generated`; `build.notes` = plan notes + cover notes + warnings.
